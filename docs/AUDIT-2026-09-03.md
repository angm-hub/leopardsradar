# Audit Léopards Radar — 03/09/2026

Audit front + back, lecture seule. Sévérités : 🔴 CRITIQUE · 🟠 MAJEUR · 🟡 MINEUR.
Chaque item porte `fichier:ligne` (ou l'objet Postgres) et un fix en une ligne.

Tableau de bord : **8 critiques · 9 majeurs · 12 mineurs**. Beaucoup de fondations saines (voir §4).

## 1. 🔴 CRITIQUE

### SEC-1 — Des RPC qui écrivent en base sont exécutables par `anon`
10 fonctions `SECURITY DEFINER` **volatiles** (elles mutent `players`) ouvertes au rôle `anon` via `/rest/v1/rpc/…` :
`apply_scores`, `apply_player_enrichment`, `apply_scouting`, `apply_sofascore_stats`, `apply_wikidata_signals`, `refresh_market_value`, `refresh_player_levels`, `snapshot_player_stats_weekly`, `compose_weekly_best_xi`, **`rls_auto_enable`**.
La clé publique est dans le bundle JS → quiconque peut appeler ces RPC et écraser scores/valeurs/données en contournant la RLS. **Le pipeline (edge functions + scripts) utilise exclusivement `service_role`**, donc révoquer `anon`/`authenticated` ne casse rien.
→ `REVOKE EXECUTE ON FUNCTION public.apply_scores(jsonb), … FROM anon, authenticated;` (+ `persist_eligibility`, `recompute_all_eligibility`).

### SEC-2 — `.env` versionné dans git
`git ls-files` → `.env`. Le `.gitignore` l'exclut désormais mais **l'historique le contient**. Si le `service_role` ou les clés API-Football y figurent = compromission totale (écriture RLS-bypass sur toute la base).
→ Roter service_role + clés API, purger l'historique (`git filter-repo`), secrets uniquement en Edge Function Secrets / GitHub Secrets / table `app_config`.

### SEC-3 — Edge function `sync-matches` sans authentification
`supabase/functions/sync-matches/index.ts:103` : aucun `x-sync-token` (contrairement à `sync-matches-apifootball/index.ts:89`). N'importe qui peut déclencher des upserts sur `matches`.
→ Ajouter la gate token partagée, ou supprimer la fonction (remplacée par la version apifootball).

### SEC-4 — 7 vues `SECURITY DEFINER` (niveau ERROR advisor)
`v_players_tier1`, `v_home_stats`, `v_home_stats_weekly`, `v_weekly_movers`, `discovery_signal`, `v_player_levels`, `onomastic_lexicon` : s'exécutent avec les droits du créateur, contournent la RLS de l'appelant.
→ `ALTER VIEW … SET (security_invoker = on);`

### PROD-1 — Aucun moteur d'éligibilité : la règle FIFA n'est calculée nulle part
`scripts/sync_transfermarkt.py:358` : `recompute_all_eligibility` **désactivée depuis le 17/05/2026** (ne gérait pas les cap-tied). `computed_eligibility_status` est **recopié à la main** aux audits. Aucun code ne calcule « ≤3 capes A compétitives, aucune en phase finale » (art. 5-9 FIFA 2020), ni n'alimente `switch_window` / `computed_eligibility_blockers`. **Cause-racine des désyncs** nettoyées le 03/09 : elles se reformeront au prochain import.
→ Réécrire `recompute_all_eligibility` en SQL déterministe (consomme `caps_rdc` + `caps_other_count` + dates/nature des capes), rebrancher, faire de `computed_*` la seule source de vérité.

### SCHEMA-1 — Dérive de schéma : les colonnes cœur ne sont dans aucune migration
`radar_tier`, `computed_eligibility_status`, `computed_eligibility_blockers`, `switch_window` : absentes de `supabase/migrations` et `scripts/migrations`, appliquées ad-hoc en base, mais référencées par edge functions et vues. **La base n'est pas reproductible depuis le repo.**
→ `supabase db dump` + committer une migration de rattrapage.

### PERF-1 — `usePlayers` refetch le pool complet (~2276 lignes) à chaque montage/filtre
`src/hooks/usePlayers.ts:44-145` : `useState`/`useEffect` maison, hors React Query (pourtant configuré, `App.tsx:49`). Radar, Roster, MaListeV2 repaginent tout le pool à chaque render/filtre ; naviguer et revenir refait un fetch intégral.
→ Migrer vers `useQuery` (queryKey sur filtres + staleTime), ou filtrer/paginer côté serveur PostgREST.

### PERF-2 — Chunk initial 777 Ko (237 Ko gzip) : framer-motion + lenis eager
`src/App.tsx:10,63` (lenis `SmoothScroll` wrappe tout, statique) + `components/home/LeopardsHero.tsx:2` (framer-motion eager → porte le LCP). Le shader Paper et colorthief/html-to-image sont bien splittés.
→ `LazyMotion` + composant `m` pour framer-motion ; lenis en import dynamique.

## 2. 🟠 MAJEUR

### DATA-1 — 3 hooks filtrent encore l'éligibilité sur le legacy seul → inéligibles fuités
`src/hooks/usePlayerSearch.ts:56`, `useRelatedPlayers.ts:40`, `useTier1Clubs.ts:32` font `.neq("eligibility_status","ineligible")` sans croiser `computed_eligibility_status`. (Le correctif du 03/09 a couvert les 4 gates client-side ; ces 3 requêtes serveur restent à faire.) Recherche, joueurs liés, clubs tier1 peuvent surfacer un joueur `INELIGIBLE`.
→ Ajouter `.or("computed_eligibility_status.is.null,computed_eligibility_status.neq.INELIGIBLE")` (null-safe côté PostgREST).

### DATA-2 — Le front lit partout le tier legacy `tier`, jamais `radar_tier`
`grep radar_tier src` = 0. Badges `components/roster/RosterCardFC.tsx:68,88`, filtre `pages/Radar.tsx:378`, `useTier1Clubs.ts:30` lisent `tier` (tier1/tier2). Si la source de vérité est `radar_tier`, les badges/filtre sont potentiellement périmés.
→ Trancher la colonne canonique, l'ajouter au `select` de `usePlayers`, migrer badges + filtre.

### QUAL-1 — 48 casts `(supabase as any)` désactivent le typage DB
`usePlayers.ts:103`, `useBestXI.ts:47`, `usePlayerAttributes.ts:56,89,107`, `lib/maListeApi.ts:72,109,121`… Une faute de colonne/RPC échoue silencieusement au runtime (retour vide) au lieu de casser à la compile — c'est le terreau des désyncs (DATA-1/2).
→ `supabase gen types`, puis retirer les `as any` progressivement.

### BACK-1 — `update-player-stats` : SELECT non borné → plafond PostgREST 1000 silencieux
`supabase/functions/update-player-stats/index.ts:124` charge tous les joueurs non-`ineligible` sans `.limit()`/pagination. Au-delà de 1000, les joueurs suivants ne reçoivent jamais leurs stats, sans erreur. Idem client Python `scripts/supabase_client.py:113` (pas de pagination ni retry 429/5xx).
→ Paginer via `.range()` en boucle (déjà fait dans `build-sitemap.mjs:84`).

### BACK-2 — Edge functions filtrent sur le legacy `eligibility_status`
`sync-players-apifootball/index.ts:68`, `update-player-stats/index.ts:127` : filtre legacy, alors que le front/tiering s'appuie sur le computed. Rien ne synchronise les deux paires → re-désync post-03/09.
→ Migrer les filtres serveur sur `computed_eligibility_status`, ou trigger de cohérence transitoire.

### BACK-3 — `og-ma-liste` (endpoint public) utilise `service_role`
`supabase/functions/og-ma-liste/index.ts:380` : génération d'image OG publique (CORS `*`) instanciée en `service_role`. Sur-privilège inutile, élargit la surface de la clé.
→ Utiliser la clé anon/publishable (lecture via policies publiques).

### PERF-3 — `PlayerAvatar` sans `loading="lazy"` ni `width`/`height`
`src/components/ui/PlayerAvatar.tsx:109` : image rendue 40+ fois par vue liste (`Radar.tsx:631`) → downloads eager en cascade + CLS.
→ `loading="lazy"` + `width`/`height` (ou `aspect-ratio`).

### SEC-5 — 14 fonctions avec `search_path` mutable (WARN advisor)
Dont `compute_eligibility`, `persist_eligibility`, `recompute_all_eligibility`, `apply_*` (les read-only `get_*`/`has_role` l'ont déjà). Vecteur d'escalade sur `SECURITY DEFINER`.
→ `ALTER FUNCTION … SET search_path = '';` (ou schéma explicite).

### PERF-4 — Lenis détourne le scroll global (INP desktop)
`src/components/motion/SmoothScroll.tsx` wrappe `App` (`App.tsx:63`). Bien géré en reduced-motion/`hover:none`, mais pèse sur l'INP du scroll long des listes.
→ Mesurer INP avec/sans ; restreindre Lenis aux pages éditoriales si gain marginal.

## 3. 🟡 MINEUR

- **SEO-1** `pages/BestXI.tsx:304` : JSON-LD `url` codé en dur `angm-hub.github.io` (injecté runtime, non réécrit par le plugin) → structured data sur le mauvais host. Idem `pages/Cgu.tsx:18`. → dériver de `window.location.origin`.
- **SEO-2** Home `/` sans `<link rel="canonical">` (`build-prerender.mjs` omet `/`). → ajouter `/` au prerender.
- **SEO-3** OG/canonical dépendent de `process.env.VERCEL` + défaut `leopardsradar.vercel.app` ; fragile sur domaine custom sans `SITE_BASE`. → définir `SITE_BASE` explicite en env prod. (Note : sur Vercel actuel, le plugin réécrit `index.html` github.io→vercel.app, donc **pas totalement cassé** — juste fragile.)
- **SEC-6** `dangerouslySetInnerHTML` JSON-LD `pages/BestXI.tsx:285` : `JSON.stringify` n'échappe pas `</script>` (XSS théorique, source contrôlée). → échapper `<` en `<`.
- **SEC-7** 5 vues matérialisées exposées à l'API anon (`mv_eligibility_pipeline`, `mv_club_concentration`, `desabre_xi_stats`, `mv_profile_insights`, `mv_generation_overview`). → révoquer anon si non nécessaire.
- **SEC-8** Extensions `pg_net`, `unaccent` dans `public`. → déplacer dans un schéma dédié.
- **BACK-4** `matches` alimentée par 2 clés d'upsert disjointes (`external_id` vs `fixture_id`) → doublons si les deux tournent. Liste `FROZEN` de fixtures codée en dur (`sync-matches-apifootball/index.ts:149`). → source unique + colonne `is_frozen`.
- **BACK-5** Pas de retry/backoff sur 429 API-Football (edge functions). → retry exponentiel borné.
- **BACK-6** Upload photo sans validation content-type (`migrate-player-photo/index.ts:171`) — endpoints admin-gated donc risque faible. → valider `Content-Type` + borner la taille.
- **QUAL-2** `ogl` déclaré dans `package.json`, jamais importé (dead dep). → retirer.
- **QUAL-3** `CommandPalette` monté en permanence (`Navbar.tsx:209`) → 2 `usePlayers` sur chaque page, palette fermée. → `enabled: open`.
- **QUAL-4** 28 `console.error/warn` en prod (pas de `console.log` dans `src`). → gate `import.meta.env.DEV` (facultatif).
- **A11Y-1** Reduced-motion : bien géré en JS mais le CSS global ne coupe qu'une animation (`index.css:265`). → règle large `@media (prefers-reduced-motion: reduce)`.
- **INFO** 13 tables « RLS enabled, no policy » (`app_config`, `caps_audit_findings`…) = **voulu** (accès service_role only, stockage secrets). Vérifier que `club_map` relève bien de ce choix et non d'un oubli.

## 4. ✅ Fondations saines (à conserver)
Token/secret sur 4/5 endpoints de mutation · zéro clé API en dur dans scripts/functions · endpoints photo gardés par `has_role('admin')` · upserts idempotents · garde-fou anti-homonyme (`update-player-stats:83`) · `<html lang="fr">` + theme-color · skip-to-content WCAG (`App.tsx:70`) · code-splitting par route + lazy sections home · états loading/empty/error complets (Radar/Roster/Player/Compare) · 404 joueur `noindex` · images décoratives `alt=""` · rendu par lots Radar · cache immutables + fonts self-host préchargées · shader/colorthief/html-to-image bien lazy.
